# 战斗资源缺口与生产清单

本清单以当前 `master` 中的运行时消费者、`SoundCatalog.Catalog` 和资源完整性测试为准。`generated` 仅表示项目内确定性生成器已经产出可运行资源；`placeholder-generated` 仅表示可重复生成的本地占位音频。两种状态都不代表已取得最终商业美术或音频授权。

统一验收基线：所有外部文件在导入前必须保存来源链接、作者、许可证文本、取得日期和修改记录。替换同路径资源时不得改动运行时代码；`CombatAssetGenerator.WriteIfMissing` 会保留已有文件。战斗图集采用透明背景、统一脚底中心 Pivot `(0.5, 0)`、`Sprite (2D and UI)`、Multiple、64 PPU、Point、Clamp、关闭 mipmap、Uncompressed；角色和普通敌人每帧 `64x64`，Elite/Boss 每帧 `96x96`。音频统一为 44,100 Hz、单声道、16-bit PCM WAV，并按表内时长交付。

当前 `Assets/Scripts/Game/BattleSceneSetup.cs:225 CreatePlayer` 和 `Assets/Scripts/Game/Dungeon/WaveSpawner.cs:96 CreateEnemy` 只创建 `SpriteRenderer`，没有创建或消费 `Animator`。未来实现必须在 `BattleSceneSetup` 声明 player、Grunt、Archer、Elite、Boss 五个 serialized `RuntimeAnimatorController` 字段，并在 `Assets/Scenes/BattleScene.unity` 分别指派表中的 `Assets/Art/.../*.controller`。Add serialized `RuntimeAnimatorController` fields to `WaveSpawner`: `gruntAnimatorController`、`archerAnimatorController`、`eliteAnimatorController`、`bossAnimatorController`；`BattleSceneSetup.CreateWaveSpawner` 在动态创建组件后通过明确的配置方法传入四个 controller。

`CreatePlayer` 与 `CreateEnemy` 必须在 `SpriteRenderer` 后调用 `AddComponent<Animator>()` 并设置 `runtimeAnimatorController`；生产状态映射固定为 `Speed -> Idle/Run`、`Attack trigger -> Attack`、`Hurt trigger -> Hurt`、`Dead -> Death`。未来 `Assets/Tests/PlayMode/CombatAnimatorResourceTests.cs` 必须通过生产创建路径分别实例化 Player、Grunt、Archer、Elite、Boss，断言每个 `Animator` 和 controller 非空，并实际驱动、观察五个状态/trigger 转换。
